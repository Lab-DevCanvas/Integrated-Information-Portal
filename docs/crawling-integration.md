# crawling 백엔드 연동

요구사항별 구현 상태·로컬 코드와 배포본 차이·검증 내용은 [백엔드·프론트 상태 보고서](backend-frontend-status.md)를 참고한다.

## 연결 설정

```dotenv
CRAWLING_API_URL=http://localhost:8000
```

`.env.local` 또는 배포 환경변수에 설정한다. 주소 우선순위는 CRAWLING_API_URL → 기존 NEXT_PUBLIC_CRAWLING_API_URL → 기존 배포 주소 http://34.59.75.165:8000 이다.


## 화면과 데이터 흐름

별도 전체 공고 목록 페이지는 제거하고 `/categories`로 통합했다. 공고 상세 `/opportunities/[id]`는 유지한다. 관리자 페이지와 관리자 전용 API 프록시는 제거했다.

카테고리 화면은 서버가 지원하는 출처·모집 상태로 요청한다. 먼저 20건과 API 전체 건수를 받아 표시하고, 나머지는 100건 단위 API 페이지를 최대 4개씩 병렬 조회하여 화면에 추가한다. 페이지 크기 변경으로 인한 누락을 막기 위해 백그라운드 조회는 100건 기준 1페이지부터 시작하고 중복 ID를 제거한다. 검색·필터·정렬은 현재 불러온 결과에 적용하므로 조회 중 순서와 결과 수가 바뀔 수 있다. 이 문제와 서버 페이지네이션 전환은 `backend-frontend-status.md`의 후속 과제에 기록했다. 전체 조회 완료 결과만 1분간 캐시하며, 백그라운드 실패 시 이미 표시한 결과와 재시도 안내를 유지한다. 조회된 항목은 로컬 메모리에도 반영하여 저장/비교에 사용한다.

| 화면 | API와 동작 |
|---|---|
| /categories | 브라우저 → /api/crawling/activities → FastAPI; 첫 20건 표시 후 나머지 백그라운드 조회; 받은 데이터에 검색·필터·정렬 적용, 스크롤 하단에서 20건씩 추가 표시; 필터를 URL에 유지 |
| /opportunities/[id] | 서버에서 GET /activities/{id} 직접 조회; 404만 notFound, API 장애는 재시도 화면 |
| 기존 대시보드 | useAllOpportunities → Zustand → 카테고리별 25건씩 최대 100건; mock을 합치지 않음; 저장/계획/비교 ID가 샘플 밖이면 단건 추가 조회 |

같은 출처 프록시를 사용해 HTTPS 프론트에서 HTTP API를 직접 호출하던 mixed-content 문제를 피한다. 고정된 서버 주소로 공고 목록·상세 GET 요청만 전달한다. 소스 관리·수집 실행·raw 조회 등 운영 경로와 쓰기 메서드는 제공하지 않는다.

## 필드 표현

상세 화면은 기존 `OpportunityDetail` UI를 유지하고 실제 API 응답을 매핑해 전달한다. 카테고리 카드 하단에 추가했던 모집 상태·원문 보기 줄은 제거했으며, 북마크·비교 아이콘은 호버와 키보드 포커스 시 도움말을 표시한다.

목록/상세는 제목·요약·출처·카테고리·기간·원문 URL·수집 시각을 사용한다. HTML을 실행하지 않고 링크는 HTTP(S)만 표시한다. source를 주최기관으로 단정하지 않는다. opportunity_id는 구버전 응답 호환을 위해 optional이며 상세 조회에는 Mongo id를 사용한다.

기존 추천 모델로 매핑할 때 dataOrigin=crawling을 기록하고 자격을 unknown으로 판정한다. 누락된 지역은 빈 배열, 시작/마감일은 빈 문자열이다. 임의의 90일 마감이나 수집일 기반 시작 일정을 생성하지 않으며 캘린더는 유효한 날짜만 사용한다.

경쟁률·포트폴리오·경력·팀 여부의 고정값은 기존 로컬 모델 호환용이다. 기존 상세 UI의 점수·분석 영역은 이 로컬 모델을 사용하며, 정식 백엔드 분석 결과가 아니다. 프론트 카테고리는 서버와 동일하게 공모전(contest)·대외활동(activity)·채용(job)·정부정책(government-policy) 4종을 사용한다. 중복되는 유형 필터는 제거했으며 카테고리는 복수 선택할 수 있다. 검색 파서·점수 모델은 로컬 기능이며 정식 백엔드 자격/매칭/Agent로 취급하지 않는다.

## 검증

`npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build -- --webpack`.

자동 테스트는 클라이언트 URL/오류·취소, 매핑, 부분/전체 실패, 카테고리 점진 조회·필터, 프록시 경로 제한·응답 전달을 검증한다.

카테고리 결과는 이전·다음 버튼 대신 하단 400px 이내에서 20건씩 추가 표시하는 무한 스크롤을 사용한다. 필터·검색·정렬 변경 시 표시 개수는 20건으로 초기화한다. 나머지 데이터의 백그라운드 조회는 계속 유지하며, 추가 데이터가 도착하면 하단에서 자동으로 이어 볼 수 있다. 기존 `page` URL 값은 사용하지 않는다.

## AI 검색 로컬 연결

AI 검색은 `/api/ai/search` POST 프록시를 통해 백엔드 `/ai/search`를 호출한다. 서버가 반환한
카드·비교·지원 계획·근거를 표시하며 브라우저의 로컬 적합도 점수를 다시 계산하지 않는다.
프로필 없이 검색할 수 있고 대화별 취소·재시도와 늦은 응답의 원래 대화 연결을 지원한다.

로컬 백엔드를 8000번 포트에서 실행한 뒤 다음과 같이 프론트를 실행한다. 키는 백엔드에만 둔다.

```bash
CRAWLING_API_URL=http://127.0.0.1:8000 npm run dev
```

`/search`에서 질문한다. 서버의 AI 기능 플래그와 DB 설정이 필요하다. 합성 예제 공고는 실제 모집이
아니며 원문이 없는 데이터는 구조화 정보로 표시한다. 재정렬 인증과 실제 공고 품질 평가는 별도다.

### RAG 테스트 VM 연결

AI 전용 서버 주소는 서버 환경변수 `RAG_API_URL`로 지정한다. 로컬에서 미설정 시 기존 공고 API 주소를
사용한다. Vercel에서는 `RAG_API_URL`과 `RAG_API_TOKEN`이 모두 필요하다. 로컬 `.env.local`은 `RAG_API_URL=http://127.0.0.1:18001`로 설정하고 SSH 터널을 유지한다.
일반 목록·상세는 기존 `CRAWLING_API_URL`을 사용한다. 환경변수 변경 후 개발 서버를 재시작한다.

```bash
gcloud compute ssh taco-rag-pilot-vm --project=taco-infocrawling --zone=us-central1-a -- -N -L 18001:127.0.0.1:8001
npm run dev
```

`/search`에서 추천 후 카드에 표시된 번호로 “1·2번 공고 비교해줘”, “1번 지원 계획을 짜줘”를
요청한다. 최근 결과 ID와 최근 대화 6개를 함께 보낸다. 터널 주소는 로컬 테스트 전용이므로
외부 배포 환경에서는 고정 IP의 HTTPS 주소를 `RAG_API_URL`에 넣는다. 서버 전용
`RAG_API_TOKEN`은 Vercel Production의 민감 환경변수로 저장하며 `NEXT_PUBLIC_` 접두사를 사용하지 않는다.
프록시는 이 토큰을 Bearer 헤더로 전송하고 리다이렉트를 거부한다. 토큰이 있으면 평문 HTTP는
거부하며 Vercel에서 설정이 빠지면 503을 반환한다. 브라우저는 계속 같은 출처 `/api/ai/search`를
호출한다. 사용자 로그인은 별도이며 서버 인증 토큰을 브라우저에 전달하지 않는다. LLM 키는 프론트에 넣지 않는다.

### 검색 카드의 원문 필드와 중복 출처

AI 검색 카드는 서버가 확인한 기관·혜택 원문·지역·지원 대상 안내를 표시한다. 자격 안내가
있어도 모든 조건을 충족했다고 단정하지 않는다. 같은 공고를 묶은 결과는 다른 출처 링크를
접어서 표시하며, 비교·계획에는 대표 카드 ID를 보낸다. 새 필드는 선택 사항으로 처리해
이전 저장 대화와 기존 API 응답도 계속 표시한다.


## AI 채팅 진행 스트리밍

AI 검색 클라이언트는 같은 POST 경로에 `Accept: text/event-stream`을 요청한다. 서버 프록시는
응답 body를 버퍼링하지 않고 전달한다. progress 단계는 대화별 임시 상태이며 저장하지 않는다.
result가 도착해야 답변·카드를 대화에 저장하고, error 이벤트는 기존 오류 코드 안내를 사용한다.
종료 이벤트 없는 연결 중단은 재시도 가능한 오류다. 취소·완료 후 진행 상태를 제거한다.
JSON 응답도 지원하므로 서버 배포 전후에 호환된다. 재연결이나 자동 재요청은 하지 않는다.

상태 문구는 실제 단계 이벤트에 따라 전환하며 완료 단계는 펼쳐 볼 수 있다. 카드의 지원 조건과
혜택은 접어 두고 제목·마감일·추천 이유를 먼저 표시한다. 답변 완료 시 마지막 카드가 아니라
답변 시작점으로 이동한다. 애니메이션은 움직임 줄이기 설정을 존중한다.

### 검색 소개와 비교 액션 (2026-10-28)

검색 답변은 반환된 공고 수를 안내하고 기존 근거 기반 소개·추천 이유를 표시한다. 이 수는 전체 DB 검색 총계가 아니라 이번 응답에 포함된 공고 수다. 2개 이상이면 ‘이 공고들 비교하기’ 버튼으로 후속 채팅을 보낸다.

버튼은 해당 답변의 ID 순서를 `previous_result_ids`에 명시해, 뒤에 다른 검색을 했어도 대상이 바뀌지 않게 한다. 사용자 메시지의 `comparisonTargetIds`를 저장하여 취소·오류 후 재시도에도 재사용한다. 동일 대화의 요청이 처리 중이면 비교 버튼을 비활성화한다. 기존 백엔드의 단순 비교 해석과 원장 재조회·근거 검증을 사용하며 API 계약 변경은 없다.

비교 응답은 데스크톱에서 표, 작은 화면에서 동일 항목의 카드로 보여준다. 마감일·지원 조건·혜택은 응답 공고 필드에서, 장점·확인할 점은 비교 응답에서 가져온다. 누락 항목은 확인 필요로 표시한다. 각 답변에서 기본으로 전체를 선택하며, 카드별 ‘비교에 담기/담김’ 토글·전체 선택·전체 해제로 비교 대상을 조절한다. 선택한 2~10개만 원래 표시 순서로 전송한다. 0~1개 선택 시 비교 버튼을 비활성화하고, 단일 공고는 제목 링크로 열도록 안내한다. 선택은 답변별 화면 상태이며 새로고침하면 전체 선택으로 돌아간다.
